# Private JobMatch (Midnight)

A zero-knowledge job-matching smart contract on [Midnight](https://midnight.network). An employer publishes job requirements on-chain, and a candidate proves they meet them **without revealing their experience, education, skills or salary expectation**. Only a single yes/no result is made public.

Built with Compact (Midnight's smart contract language) and TypeScript. This is a proof of concept.

## How it works

**Public (on-chain ledger)**

| Field | Meaning |
|---|---|
| `minimumExperience` | Minimum years of experience required |
| `degreeRequired` | Whether a degree is required |
| `javascriptRequired` | Whether JavaScript skill is required |
| `maximumSalary` | The most the employer will pay |
| `lastMatch` | Result of the most recent match check (`true` / `false`) |

**Private (candidate's machine only)**

| Witness | Meaning |
|---|---|
| `getExperience` | Candidate's years of experience |
| `getHasDegree` | Whether the candidate has a degree |
| `getHasJavaScript` | Whether the candidate knows JavaScript |
| `getExpectedSalary` | Candidate's expected salary |

These four values live in a local `JobMatchPrivateState` object (`src/witnesses.ts`). They are fed into the circuit as witnesses and are never written to the ledger.

**Circuits**

- `setJobRequirements(minExperience, requiresDegree, requiresJavaScript, maxSalary)` writes the four public requirements to the ledger.
- `checkMatch()` reads the candidate's private values, compares them with the public requirements, and discloses only the final boolean as `lastMatch`.

A candidate matches when all four conditions hold:

1. `experience >= minimumExperience`
2. a degree is held, or none is required
3. JavaScript is known, or not required
4. `expectedSalary <= maximumSalary`

The zero-knowledge proof for `checkMatch` is generated by the proof server, which runs locally by default, so private inputs stay on your machine.

## Run it locally

Requirements: Node 22, Docker (with Compose v2), and the Compact compiler.

```bash
npm install
npm run setup      # starts the local devnet, compiles the contract, deploys it
npm run cli        # interactive CLI to call the circuits
```

Other scripts: `npm run compile`, `npm run deploy`, `npm run check-balance`, `npm run clean`.

> **Local devnet only.** The deploy script uses a well-known genesis seed that is only safe on the bundled local devnet. Never use it on Preprod, mainnet, or anywhere real value is involved.

## Project structure

```
contracts/jobmatch.compact   # Compact contract: ledger, witnesses, circuits
src/witnesses.ts             # private candidate state + witness implementations
src/                         # wallet, network, deploy and CLI scripts
docker-compose.yml           # local node + indexer + proof server
```

## Limitations and next steps

This is an early proof of concept, and these gaps are known:

- **No access control.** Anyone can call `setJobRequirements`, so anyone can overwrite the requirements. Next step: restrict it to the employer with a public-key commitment checked inside the circuit.
- **One shared result.** `lastMatch` is a single value overwritten by each check and is not tied to a candidate. Next step: store results per candidate, keyed by a commitment.
- **One bit of information is public.** Each check reveals a yes/no, so repeated checks against different requirements could reveal more about a candidate over time.
- **Single-job model.** The contract holds one set of requirements at a time.
- **No UI yet.** Interaction is through the CLI.
